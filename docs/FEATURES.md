# Features

Every trim feature: how it works and what it gives you.

Current release: 0.2.0

**Since** is the release that added the feature. `Unreleased` means it is on `main` but not in a release yet.

## Update this file at each release

1. Add a row for each new feature, with **Since** set to `Unreleased`, when the feature lands. Change a row when a release changes how its feature works; remove the row when the feature is removed.
2. At release, change every `Unreleased` to the new version, and set `Current release:` above to the version in the plugin's `plugin.json`.

## Features

| Feature | How it works | Value | Since |
|---|---|---|---|
| Half-size browser screenshots | A hook adds `scale: 0.5` to each desktop-app browser screenshot that sets no scale. Clicks still land. Claude can ask for full size with `scale: 1`. Off: `TRIM_BROWSER_SCALE=off`. | About 75% fewer tokens per screenshot (estimate). | 0.1.0 |
| Tips in `/trim:setup` | Setup lists short rules you can turn on. First tip: text-first browsing, with `scale: 0.5` in batch screenshots so auto mode does not refuse batches. A hook adds the tips you chose from the next session. Stored in `~/.claude/trim/tips.json`; untick in setup to remove. Off: `TRIM_TIPS=off`. | Costs about 59 tokens per session (estimate); saves one extra turn per refused batch and fewer screenshots. | 0.1.0 |
| Command output caps | A hook pipes the output of simple test and build commands (pytest, unittest, jest, npm test, cargo, go, make, tsc and others) into trim; commands with shell operators such as `&&` or `|` are left alone, so permission rules still see every part. Output over 150 lines comes back with every failure line, every summary line (such as `Ran N tests` / `OK`) and the last 40 lines; the full copy is saved in `~/.claude/trim/out/` and its path is named. Failure lines include TypeScript `error TS1234`, `npm ERR!`, git `fatal:`, ESLint errors and make `Error N`, not only test-runner failures. Runs of 3 or more progress or pass lines (such as `PASS` or `ok`) among the kept lines become one count line. Exit codes are kept. Off: `TRIM_OUTPUT_CAP=off`. | About 80% fewer tokens on a long failing test run (one demo: 632 lines to 100). | 0.1.0 |
| Connector result cleanup | A hook cleans connector (MCP) results before Claude reads them: long base64 data becomes a short note, empty JSON fields are removed, and lines repeated 3 or more times in a row are collapsed, and so are runs of 3 or more progress or pass lines (`Downloading ...`, `Compiling ...`, `PASS ...`, check marks) into one count line; a failure or summary line never joins a run. Only results over 2,000 characters that shrink at least 10%; images are left alone. The full copy is saved in `~/.claude/trim/out/` and its path is named. Results over Claude Code's MCP output limit are already saved to a file by Claude Code; trim does not change them. Off: `TRIM_TOOL_CLEANUP=off`. | Large savings on connector answers with attachments or logs (one demo: 7,595 to 190 characters). | 0.1.0 |
| Smaller image reads | When Claude Reads a `.png` or `.jpg` file with a long edge over 1,250 px, and the estimated saving is at least 500 tokens, a hook points the Read at a copy with a long edge of 1,000 px. The original file is never changed; the copy is saved in `~/.claude/trim/out/` and deleted after 7 days. Needs `sips` (macOS) or ImageMagick; with neither, nothing changes. Pasted or attached images are not changed (a plugin hook cannot do that). Off: `TRIM_IMAGE_SHRINK=off`. | Estimate: a 1080x1920 phone screenshot saves about 2,000 tokens; wide, short images are left alone. Small text can blur at 1,000 px. | 0.2.0 |
| Repeat reads | When Claude Reads a file again with the same arguments (same offset, limit and pages) and the file has not changed since its last Read, a hook stops the Read and tells Claude the earlier result is still in the conversation. If Claude Reads it a third time, the Read goes through. After a compact or clear, Reads go through again. Subagents are untouched, and so are files under 2,000 bytes. Applies to the Read tool only. Off: `TRIM_REPEAT_READS=off`. | One demo: 7,671 characters per repeat read of a 5,379-byte file become a pointer of about 300. | 0.1.0 |
| Fixed context check | `/trim:context` reads this project's session transcripts (no model call, changes nothing). It shows what fills the fixed context, with tokens per part: skill list, agent list, tool names, connector instructions, CLAUDE.md and memory files, SessionStart hook output. Then it lists the agent types, connectors and plugins this project has not used in 90 days, with tokens per item and where to turn each off in Claude Code (`/mcp`, `/plugin`, `claude plugin disable --scope local`, a `permissions.deny` line, or the claude.ai Connectors page). Skills: it points to `/skill-doctor` and `/skills`. | On this repo: about 3,700 tokens per request in unused agents, connectors and plugins (estimate). | 0.1.0 |
| Savings report | Each trim hook that saves tokens appends one line to `~/.claude/trim/savings.jsonl` (time, feature, characters before and after, estimated tokens saved, path of the full copy). `/trim:report` shows each feature for all time, the last 30 days and the last 7 days, and the last 5 sessions. Half-size screenshots use a fixed assumed figure (505 tokens each) and image shrinks use a pixel-count estimate; both are marked "assumed". The log cleans itself: past 100 KB, the next write drops lines older than 90 days and keeps the file under 1 MB. Dropped lines are first added to a small per-day totals file (`savings-totals.json`), so all-time totals stay; session detail is kept about 90 days. `/rightsize report` can read the same file (format: ADR 0012). Off: `TRIM_SAVINGS=off`. | Shows what trim actually saved, with no rightsize needed. The file stays small with no manual step. | 0.1.0 |
